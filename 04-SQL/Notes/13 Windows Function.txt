╭────────────────────────────────╮
│    🌟📥 WINDOW FUNCTION🌟     │
╰────────────────────────────────╯


A Window Function performs a calculation across a set of related rows without combining them into a single row.

👉 Unlike GROUP BY, it keeps all original rows in the result.

OVER clause is used with window functions to define that window



━━━━━━━━━━━━━━━━
🔑 Important Parts
━━━━━━━━━━━━━━━━


🔸OVER()
Defines the window on which the function operates.


🔸PARTITION BY
Divides the rows into groups, but does not combine them.


🔸ORDER BY
Defines the order in which the window function processes/ranks the rows.

💡Window Function

It applies aggragate, ranking and analytic functions over a particular window
Example: SUM, AVG or row_number



💡Expression

It is the name of the column that we want the window function operated on. This may not be necessary depending on what window function is used.



💡OVER

It is just to signify that this is a window function



💡PARTITION BY

It divides the rows into partitions so we can specify which rows to use to compute the window function



💡ORDER BY

It is used so that we can order the rows within each partition.
This is optional and does not have to specified.




💡ROWS

It can be used if we want to further limit the rows within our partition.
This is optional and usually not used.

There are no official division of the SQL window functions into categories but high level we can divide into three types.



1️⃣AGGREGATE

	🔸SUM
	🔸 AVG
	🔸 COUNT
	🔸 MIN
	🔸 MAX



2️⃣ Ranking

	🔸ROW_NUMBER
	🔸 RANK
	🔸 DENSE_RANK
	🔸PERCENT_RANK



3️⃣ Analytic / Value

	🔸 LEAD
	🔸 LAG
	🔸FIRST_VALUE
	🔸 LAST_VALUE





Syntax:

SELECT column_name(s),
	aggregate_function() OVER ( [ < PARTITION BY Clause > ]
			      [ < ORDER BY Clause >]
			      [ < ROW or RANGE Clause > ] )
FROM table_name;








👉 Example:

SELECT id, name,
    SUM(id) OVER (PARTITION BY name) AS "Total",
    AVG(id) OVER (PARTITION BY name) AS "Average",
    COUNT(name) OVER (PARTITION BY name) AS "Count",
    MAX(id) OVER (PARTITION BY name) AS "Max",
    MIN(id) OVER (PARTITION BY name) AS "Min"
FROM table1;

1️⃣ AGGREGATE



    🔸 SUM
       → Adds all values within the window.
       → Example: 10, 20, 30 → SUM = 60

    🔸 AVG
       → Calculates the average of values within the window.
       → Example: 10, 20, 30 → AVG = 20

    🔸 COUNT
       → Counts the number of rows/values within the window.
       → Example: 10, 20, 30 → COUNT = 3

    🔸 MIN
       → Returns the smallest value within the window.
       → Example: 10, 20, 30 → MIN = 10

    🔸 MAX
       → Returns the largest value within the window.
       → Example: 10, 20, 30 → MAX = 30





📍Example:


SELECT id, name,
    SUM(id) OVER (PARTITION BY name) AS "Total",
    AVG(id) OVER (PARTITION BY name) AS "Average",
    COUNT(name) OVER (PARTITION BY name) AS "Count",
    MAX(id) OVER (PARTITION BY name) AS "Max",
    MIN(id) OVER (PARTITION BY name) AS "Min"
FROM table1;

			        👉 WINDOW FRAME 👈

━━━ UNBOUNDED PRECEDING → UNBOUNDED FOLLOWING ━━━


💡 Means:

→ Include ALL rows in the window,
  from the first row to the last row & apply Aggregate functions.



📌 Syntax:

ROWS BETWEEN UNBOUNDED PRECEDING
     AND UNBOUNDED FOLLOWING



 
📌Meaning
 UNBOUNDED PRECEDING → Start from first row
 UNBOUNDED FOLLOWING → Go up to last row



📍Example:


SELECT id, name,
	SUM(id) OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS sum,
    AVG(id) OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS avg,
    MIN(id) OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS min,
    MAX(id) OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS max,
    SUM(id) OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS sum
FROM table1;

╔══════════════════════════════════════════╗
║   🔷 WINDOW FUNCTION + RANKING 🔷     	║
╚══════════════════════════════════════════╝


🔸ROW_NUMBER() 


       → Assigns a unique sequential number to every row.
       → Even when values are the same, row numbers are different.

       Salary:       		50000     50000   40000
       ROW_NUMBER:            1       	2        3






    🔸 RANK()

       → Assigns the same rank to rows having the same value.
       → Skips the next rank after a tie.

       Salary:       50000   50000   40000   30000
       RANK:             1       1       3       4
                                      ↑
                                Rank 2 is skipped






    🔸 DENSE_RANK()
       → Assigns the same rank to rows having the same value.
       → Does NOT skip the next rank after a tie.

       Salary:       	    50000   50000   40000   30000
       DENSE_RANK:      1           1          2          3
                                    	  		↑
                               		 No rank is skipped





    🔸 PERCENT_RANK()
   
       → It tells you how far a row has moved through the ranking, from first to last.

	→ Returns a value between 0 and 1.

	→ It tell, How far a rank from the top position like If my percent_rank is 25% it means I am 25% far from the top rank (rank 1)

 

       Formula:

       (Rank - 1) / (Total Rows - 1)

       Example:
       Rank = 2, Total Rows = 5

       PERCENT_RANK = (2 - 1) / (5 - 1)
                    = 1 / 4
                    = 0.25

       → 0.25 means the row is at the 25% relative rank.


Example:

   Salary       Rank       PERCENT_RANK
   60000         1             0
   50000         2             0.25
   40000         3             0.50
   30000         4             0.75
   20000         5             1



   💡 In simple words:
   → 0    = First position
   → 0.25 = 25% through the ranking
   → 0.50 = 50% through the ranking
   → 0.75 = 75% through the ranking
   → 1    = Last position




👉 Example:



SELECT id, name,
	ROW_NUMBER() OVER (ORDER BY id) AS "row_number",
    RANK() OVER (ORDER BY id) AS "rank",
    DENSE_RANK() OVER (ORDER BY id) AS "dense_rank",
    PERCENT_RANK() OVER (ORDER BY id) AS "rank_percentage"
FROM table1;

ANALYTIC / VALUE

    🔸 LEAD()
       → Returns the value from a following/next row.
       → Useful for comparing the current row with the next row.

       Salary:    40000   50000   60000
       LEAD:      50000   60000    NULL
                  	      ↑          ↑
                	    Next     Next


    🔸 LAG()
       → Returns the value from a preceding/previous row.
       → Useful for comparing the current row with the previous row.

       Salary:       40000   50000   60000
       LAG:        NULL   40000   50000
                             ↑          ↑
                       Previous  Previous


    🔸 FIRST_VALUE()
       → Returns the first value from the defined window.

       Salary:       	   40000   50000   60000
       FIRST_VALUE:  40000   40000   40000
                     			↑
                  		First value


    🔸 LAST_VALUE()
       → Returns the last value from the defined window.
       → The window frame is important when using LAST_VALUE().

       Salary:       	   40000   50000   60000
       LAST_VALUE:   60000   60000   60000
                           			   ↑
                       			    Last value







👉Example:

SELECT id, name,
	FIRST_VALUE(id) OVER(ORDER BY id) AS "first_value",
    LAST_VALUE(id) OVER(ORDER BY id) AS "last_value",
    LEAD(id) OVER (ORDER BY id) AS "lead_value",
    LAG(id) OVER (ORDER BY id) AS "prev_value"
FROM table1;

💡Issue: Why LAST_VALUE() doesn't give the actual last value which is 700


Because by default, the window ends at the current row.

LAST_VALUE(id) OVER(ORDER BY id)

So if IDs are 10, 20, 30, 40:

10 → last value = 10
20 → last value = 20
30 → last value = 30
40 → last value = 40

It is finding the last value up to the current row, not the last value of the entire table.




✅ To get the actual last value


LAST_VALUE(id) OVER(
    ORDER BY id
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)



Now every row will show:

40
40
40
40



📍Remember: 
LAST_VALUE() needs UNBOUNDED FOLLOWING when you want the last value of the entire window.










🔹━━━━ 🔸 LAST_VALUE() WITH FULL WINDOW 🔸 ━━━━🔹

    LEAD(id) OVER (ORDER BY id) AS "lead_value",
    LAG(id) OVER (ORDER BY id) AS "prev_value"
FROM table1;
